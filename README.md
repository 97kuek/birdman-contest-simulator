# 鳥人間コンテストシミュレーター

東京理科大学・鳥科の2025年滑空機「竜海」と、松原湖岸のプラットフォームをメートル単位で表示するThree.jsプロトタイプ。画面の「資料・出典」から原典を参照できる。

[ブラウザでプレイする](https://97kuek.github.io/birdman-contest-simulator/)

## 起動

```sh
npm ci
npm start
```

ブラウザで端末に表示されたローカルURLを開く。インストール後は、機体・地形・航空写真の表示にインターネット接続は不要。静的配信用には `npm run build` で `dist/` を生成する。

## 操作

「飛行準備」で風を選んで開始する。プラットフォームで ← → を押すと機首が1°ずつ動き、Space で向きが決まる。発進コールは字幕で表示し、「GO」で3人が走り出す。

飛行中は ← → でラダー、↑ ↓ で前後の体重移動。スマホでは、発進前の左右矢印をタップすると1°ずつ、長押しすると連続で向きが変わる。「発進」をタップして離台する。飛行中は左手で「体重移動」の前・後、右手で「ラダー」の左右を押す。同時に押せて、指を離すとその入力が中立に戻る。パイロット視点では景色を上下左右にドラッグしても操縦できる。視点はパイロット・ボート・俯瞰から選べる。着水から約2秒後にボート視点へ移り、機体が落ち着くと飛行距離を表示する。続けて「再挑戦」「リプレイ」を選べる。

操縦席の液晶で対気速度と水面までの高さを読む。中央の水平線は機体のピッチ・バンクに応じて傾き、下段には昇降速度、ラダー、進路、風を表示する。風の矢印は機首を上とした風の流れを示す。リプレイで時刻を変えると液晶もその時点の表示に戻る。

## 再現範囲

- 機体は三面図をもとに翼弦、上反角、ねじり下げ、胴体、尾翼を再構成した。写真に合わせて主翼の前縁外板・被覆・桁・リブ、透明機首のフレームと操縦席、胴体の波模様、尾翼の金具、上部の風向ベーンを造形した。独自翼型、塗装、内部の形状には近似がある。翼幅変更時は区間幅を比例変更して翼弦を保つ。[鳥科の機体資料](https://torica-tus.com/2025/11/14/2025/)
- 地形は実標高、地表はオルソ画像。松原湖岸の近景は約4 km四方を約7.8 mの頂点間隔にした。湖面は基準水位、建物の高さと樹木は推定。プラットフォーム付近の約1.0 × 1.5 kmにはさらに細かい地形メッシュ・航空写真を重ねた。データの解像度と近似の範囲は[松原湖岸の出典](assets/terrain/source.md)に記載。
- プラットフォームは水面上10 m・助走路10 m・3.5°を採用。裾幅、支柱、方位は近似。搬入路は推定方位での水際まで約168 mとしている。プラットフォームの表面にパネルの継ぎ目と塗膜の質感を加えた。湖面には空、機体、桟橋、湖岸の樹木・建物・地形を映す。[主催者の規定](https://www.ytv.co.jp/birdman/about/)
## 飛行比較

機体は25.1 mの主翼と翼根取付角3.2°の竜海で、全備質量100 kg。プラットフォームは固定で発進方向を左右30°まで選べる。標準の押力で正面へ助走したときの台端の対地速度は8 m/s。各試技は同じ風・発進方向の比較用基準機を持つ。リプレイでは離台後10秒の高度・対気速度・ピッチと、体重移動・ラダー入力の履歴を確認できる。

- 主翼・水平尾翼の空気力、重力、ピッチ運動を120 Hzで積分する。鳥科の竜海用訓練モデルの空力係数を参照し、離台後の体重移動と低空での引き起こしを近似した。同じ気象内では各試行に同じ風の分布を適用する。翼幅を変えると主翼面積とアスペクト比が変わる。質量と慣性は固定している。
- 飛距離は最初の水面接触時に台端から機体最後尾までを測った水平直線距離。3Dの線は重心軌跡。接水後は直前の対地速度と進行方向を引き継ぎ、4秒間かけて減速し、機体が浮かぶ姿勢に落ち着く。この区間は実測に基づかない視覚的な近似で、飛距離と滞空時間には含めない。
- 基準機の現在の試算は430.7 m・55.6秒。[引き起こしの検証](docs/pullup-validation.md)にデータの処理と切り分け結果をまとめた。飛行映像の時刻、実測ログとの区間比較、モデルの仮定と残差は[飛行モデルの検証](docs/flight-validation.md)に記載した。
- `npm test` で発進条件、再現性、機体設定の効果、水面接触、旋回を含む距離計測、実機ログに対する区間別の許容幅を確認できる。

[実機との誤差と物理モデルの監査](docs/physics-audit.md)には、離台後10秒の対気速度・姿勢、旋回中の固定風の修正、実測が足りない項目をまとめた。

竜海のラダー機構、大会GPSから測った対地方位の変化率、現行の旋回モデルとの比較は[左右操舵の検証](docs/steering-validation.md)にまとめた。

## 湖面と風

湖面は複数方向・6波長帯の重力・毛管波を合成し、近景の水面の高さ、波面の傾き、反射像、太陽のきらめきを描く。波長は約0.15〜9.7 mで、進む速さは重力と表面張力を含む深水波の分散関係から求める。浅瀬は写真に沿って波高と見える水底色を変える。短すぎて画素が解像できない波は弱める。雲は風向に移動し、着水位置には時間とともに減衰する波紋を表示する。波高・水深・雲量は当日の実測ではない。水面高の基準を保つため、飛距離の採点には平均湖面との最初の接触を使う。

準備画面の風は無風・向かい風・追い風・横風の4種類。台の正面に対して風速を指定し、有風時は一定の1.2 m/s、横風は左から吹く。飛行計算と風向計では現在の機首を基準に風を分解する。波と雲も風向に応じて進む。過去のログに合わせた風の分布は開発用の検証に使用する。

## コードの構成

| 場所 | 担当 |
| --- | --- |
| `src/domain/` | 竜海の機体諸元、発進条件、風、飛行力学、最初の接水による計測 |
| `src/application/` | 同じ風・発進方向での試技、基準飛行、条件別の記録、発進コールとリプレイ用データ |
| `src/rendering/` | Three.jsの機体・搭乗員・地形・湖面、接水判定用の機体外形、軌跡の描画 |
| `src/presentation/` | 画面の進行、タッチ・キーボード入力、字幕、風向計、記録掲示板 |
| `src/main.js` | ブラウザの起動と各モジュールの接続 |
| `analysis/`・`docs/` | 大会ログの再解析と、その検証結果・出典 |

試技の時計は「GO」を起点とし、飛行ログの時計は離台時にゼロになる。飛距離と滞空時間は最初の接水で確定する。水上滑走とボート視点への移行は結果発表の演出として扱う。

飛行計算と試技管理は、時刻と操縦入力を引数で受け取る。Node.jsのテストはブラウザを起動せずに両者を検証する。`npm test` はモジュールの依存方向も確認する。[技術選定と見直し条件](docs/technology.md)
