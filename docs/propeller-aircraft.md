# 人力プロペラ機を追加するときの設計

2026年の単座・二人乗り機を対象に、設計点と実飛行データを比較した。[CygnusとS-320の調査・実装案](human-powered-propeller.md)

最初の1機は三面図にプロペラの設計点が載っている機体を選ぶと、外形と推力を別々に照合できる。たとえば京都大学の2025年機 *Fregata* は全幅29 m、プロペラ半径1.40 m、回転数140 rpm、推力26 N、巡航速度7.9 m/s、必要パワー227 Wと公表している。これらは設計値で、飛行中の実測にはトルク・回転数・対気速度の同期記録が要る。[京都大学ShootingStarsの三面図](https://shootingstars.hannnari.com/about/siryou/sanmenzu2025.pdf)

| 対象 | 共有できる処理 | 人力機に持たせる情報と動き |
|---|---|---|
| 外形と姿勢 | Three.jsの部材・曲面、機体全体の姿勢、翼のたわみ、湖とカメラ | ハブ・クランク・座席の位置（m）、軸の向き、ブレード枚数・半径・翼弦・ねじりを三面図から与える。プロペラと左右のペダルは各軸を原点にした子オブジェクトにする。[部材生成](../src/rendering/aircraft/mesh-parts.js)・[機体姿勢](../src/rendering/aircraft-pose.js) |
| 操縦と空気力 | 固定刻みの積分、対気速度、主尾翼の揚抗力、風 | 入力するペダル回転数と出力限界、伝達比・効率から軸回転数・軸出力を求める。回転数と軸方向対気速度に応じた推力を機体に加え、重心からずれた推力線のモーメントも反映する。停止付近でも有限の推力を返す静止推力データまたは近似が要る。[飛行の積分](../src/domain/flight.js)・[力とモーメント](../src/domain/aircraft-dynamics.js) |
| 接触と再生 | 水面・岸の判定、時刻から姿勢を再現するリプレイ | 回転翼はハブ・半径・軸を共有する独立した接触形状にする。低速では刃先、高速で円板近似を用いる場合は台や水面に最初に触れる時刻の差を検証する。クランクとプロペラの累積回転角を記録し、停止・コマ送り・逆方向シークでも同じ姿勢に戻す。[接触外形](../src/rendering/collision-hull.js)・[再生](../src/presentation/replay.js) |

**描画と飛行の受け渡し。** 機体ローカル座標は右が+X、上が+Y、機首が−Z。軸をどちらから見た回転方向かを資料と照合し、クランク・プロペラそれぞれの回転の正方向を定義する。飛行側が秒・rad・N・Wで状態を持ち、描画側はサンプル時刻の累積角で脚とブレードを動かす。伝達中はペダル1回転でプロペラが伝達比どおり回り、左右のペダル位相は半回転ずれる。惰性回転は対象機のフリーホイールの有無に合わせる。機体切替時は操縦者の体重移動、ラダー支点、計器の取り付け位置を機体ごとに指定する。[機体選択と組み立て](../src/main.js)・[機体諸元](../src/domain/aircraft-profiles.js)

**長距離の記録。** 現行の120秒上限、毎秒20個の姿勢サンプル、着水位置からの距離採点は短距離滑空向け。人力機では経過時間、各旋回地点の通過順・時刻、完走を保存し、大会年・部門・コース別に記録を比較する。長時間の再生は入力履歴と定期的な状態保存で容量を測る。たとえば2026年大会は南北両ルート往復で42.195 km、複数完走なら時間で順位が決まる。[現行の採点](../src/application/flight-records.js)・[読売テレビ・2026年大会概要](https://www.ytv.co.jp/birdman/about/)

**最初の検証。** ハブ位置と直径を三面図に重ね、設計回転数で1分間の回転数を数える。巡航設計点で推力と抵抗、推進仕事率（推力×対気速度）と軸出力を照合する。発進・ペダル停止時は別条件で試し、ギア比、静止推力、伝達効率のうち実機資料のない値は仮定として記録する。最後に同じ試技を30/60 fpsとリプレイのシークで比較し、旋回順の誤り・途中着水・完走の採点も確認する。
